% ABSTRACT
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{abstract}
Running neural inference on an embedded processor is flexible but leaves
latency exposed to scheduling and the software stack; moving it into
programmable logic makes latency predictable but normally ties the bitstream to
one network, so every retrained model costs a synthesis run. This paper
presents an inference engine that avoids both. The network shape is a run-time
parameter held in configuration registers, so networks of different topologies
are deployed into an unchanged bitstream over AXI-Lite with no synthesis step.
On a low-cost Xilinx Zynq-7000 the engine uses \SI{87.3}{\percent} of the DSP
slices and \SI{27.0}{\percent} of the LUTs at an estimated \SI{2.70}{\watt},
closes timing at \SI{125}{\mega\hertz}, and completes an inference in
\SI{768}{\nano\second}. An on-chip cycle counter shows this latency to be
invariant: over \num{100000} inferences the standard deviation is zero. The same
network run bare-metal on the SoC's Cortex-A9 requires
\SI{52.4}{\micro\second}, 68 times longer. The datapath was verified bit-exactly
against an independent reference model over \num{400000} inferences across four
topologies, a process that first exposed three pipeline-alignment defects
invisible to synthesis. Against the same four networks generated by hls4ml for
the same device, clock and arithmetic, over 20 design points, every one that
fits placed and routed, no design of the two larger networks meets \SI{125}{\mega\hertz},
and the fastest is 1.3 to 2.0 times slower than the engine even at its own
maximum frequency. The engine is evaluated end to end over Ethernet on a
latency-critical financial decision task.
\end{abstract}

\section{Introduction}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
Embedded systems increasingly evaluate a small neural network on every input
event, under a latency bound that must hold for the worst case rather than on
average. Running the network on the embedded processor keeps the model easy to
change but exposes latency to scheduling, interrupts, caches and the software
stack, so the distribution acquires a heavy tail. Moving the network into
programmable logic removes those sources of variation, but the usual
high-level-synthesis route binds the bitstream to one network: a retrained
model, or a change of topology, costs a synthesis and place-and-route run
measured in hours.

This paper presents an inference engine that keeps the determinism of the
fabric without that rigidity. The engine runs in the programmable logic (PL) of
a low-cost Zynq-7000 SoC, is fed over Ethernet through the processing system
(PS) and an AXI-DMA / AXI-Stream datapath, and treats the network shape as a
run-time parameter: layer widths live in configuration registers, so networks of
different topologies are loaded into an unchanged bitstream over AXI-Lite with
no synthesis step between them.

We evaluate it on a task that makes the latency requirement concrete. In
high-frequency trading the time between market data and order matters as much
as the correctness of the order: Budish et al.~\cite{Budish2015} model the
resulting latency race as an equilibrium feature of continuous limit order
books, and Aquilina et al.~\cite{Aquilina2022} find races decided on the scale
of microseconds. The workload is a three-class directional decision over
Binance BTCUSDT trade data (Section~\ref{sec:dataset}); nothing in the
architecture is specific to it.

\subsection{Main Contributions}
\begin{itemize}
  \item A 192-multiplier, 13-stage pipelined MLP core for the XC7Z020 whose
        latency follows an analytic model ($\lceil n_\ell/3\rceil + 14$ cycles
        per layer) that matches the oscilloscope and an on-chip cycle counter
        exactly in total and to within one cycle per layer.
  \item Run-time reconfigurability of the network \emph{shape}, not only of its
        weights: four topologies run in one unchanged bitstream, each at its own
        cycle count.
  \item A three-level verification (independent bit-accurate model, directed
        RTL simulation, on-hardware comparison) that exposed three
        pipeline-alignment defects invisible to synthesis and then established
        bit-exact agreement over 400{,}000 inferences and 1{,}200{,}000 raw
        outputs.
  \item An end-to-end Ethernet-to-decision measurement with a per-stage
        breakdown over $10^6$ packets, a zero-variance cycle count over
        \num{100000} inferences, and like-for-like baselines on the same SoC.
  \item A measured comparison against hls4ml for the same four networks, part,
        clock and arithmetic, over five reuse factors taken through place and
        route.
\end{itemize}

\section{Related Work}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsection{FPGA Acceleration in Financial Systems}
Leber et al.~\cite{Leber2011} moved market-data feed handling and order
generation into an FPGA and reported wire-to-wire latencies roughly an order of
magnitude below a tuned software path; Lockwood and Monga~\cite{Lockwood2015}
pursued the same argument at data-center scale. Puranik et
al.~\cite{Puranik2023} implemented an order-processing back end through
high-level synthesis at roughly \SI{500}{\nano\second} per order, and Brown et
al.~\cite{Brown2021} applied dataflow transformations to a credit-default-swap
pricing engine. LightTrader~\cite{Yoo2023} is closest in intent: an FPGA
handles the network and order path while the learned model runs on separate
deep-learning accelerator chips. In all of these the accelerated function is
fixed at elaboration time, which suits stable algorithms but not a learned model
that is retrained periodically. Learned order-book models~\cite{Zhang2019,
Ntakaris2018} are in turn evaluated offline and rarely report deployment
latency.

\subsection{Neural Network Inference on FPGAs}
The FPGA deep-learning literature has converged on compiler-style frameworks
that translate a trained network into a bitstream. Zhang et
al.~\cite{Zhang2015} formalised the underlying design-space exploration, Qiu et
al.~\cite{Qiu2016} and Angel-Eye~\cite{Guo2018} brought it to embedded Zynq
parts, FINN~\cite{Umuroglu2017} and FINN-R~\cite{Blott2018} generate dataflow
architectures for quantized networks with latencies of a few hundred
nanoseconds, and hls4ml~\cite{Duarte2018} targets the same regime for
particle-physics triggers, which share the hard latency budget of trading.
hls4ml has since become a general compiler platform~\cite{Schulte2026}, and
da4ml~\cite{Sun2026} replaces its constant matrix-vector products with
distributed arithmetic. Both gain their efficiency from weights that are
constants of the circuit. On the XC7Z020 used here, Vitis HLS has met a
\SI{70}{\micro\second} worst-case budget for cognitive radio~\cite{deBroglie2024};
in this journal, Gdaim et al.~\cite{Gdaim2026} guide an OpenCL HLS flow on a
Zynq-7000 with predictive latency and BRAM models, and Rangsikunpum et
al.~\cite{Rangsikunpum2026} run a binarized classifier on the same ZedBoard at
over 9{,}000 frames per second within about \SI{2.8}{\watt}. Edge CNN
accelerators such as SparkNoC~\cite{sparknoc} optimize energy efficiency,
Tsoutsouras et al.~\cite{Tsoutsouras2017} apply the same methodology to a
non-neural classifier, and Wang et al.~\cite{Wang2019survey} survey the field.
On SoC targets the PS--PL data movement is often the limiting
factor~\cite{RiosNavarro2018}, which the breakdown of Section~\ref{sec:latency}
reproduces. Fixed-point inference preserves accuracy for a wide range of
networks~\cite{Jacob2018,Hubara2017,Gholami2021}, and quantization noise in MLPs
can be predicted analytically~\cite{AlRikabi2024}.

All of these require a new synthesis run when the network changes, and all are
evaluated as compute kernels with the network interface outside the reported
latency.

\subsection{Run-Time Programmable Overlays}
\label{sec:overlays}
Overlays remove re-synthesis by expressing the network as data for a fixed
engine. VTA~\cite{Moreau2019} defines a tensor instruction set and compiler,
OPU~\cite{Yu2020,YuLight2020} compiles CNNs to microcode, and AMD's
deep-learning processing unit~\cite{AMDVitisAI} is a fixed overlay driven by
compiled instructions; Khaki and Choi~\cite{Khaki2025} use it for lightweight
CNNs at 6.28 to \SI{19.95}{\milli\second} per frame. Kabir et
al.~\cite{Kabir2026} carry the idea to transformers, and Ratto et
al.~\cite{Ratto2023} use run-time reconfiguration to trade time for power within
one network. SLAC's Neural Network Library~\cite{EzzaouiRahali2025} keeps
HLS-generated layers but reloads weights and biases at run time; its published
description presents this as a weight reload rather than a change of layer
dimensions. Dynamic partial reconfiguration rewrites the fabric itself:
Boudjadar et al.~\cite{Boudjadar2025} apply it on the XC7Z020 at
\SI{0.68}{\second} per image, but every module must still be synthesized in
advance and the region is out of service while it is rewritten.

We do not claim to have introduced run-time programmability. Published overlays
are throughput architectures, dimensioned for convolutional workloads and
reported per frame or per batch; among those that change the network shape
without re-synthesis we are aware of none that reports single-inference latency
below one microsecond. The present design accepts a narrower scope, fully
connected layers within fixed bounds, for a latency that is a property of a
single inference.

\subsection{The Latency Extreme}
LogicNets~\cite{Umuroglu2020} compiles quantized neurons directly into
lookup tables and reaches nanosecond latencies; later work learns piecewise
polynomials per table~\cite{Andronic2023}, hides sub-networks inside Boolean
functions~\cite{Andronic2024}, widens table inputs~\cite{Lou2024}, assembles
larger networks~\cite{Andronic2025}, and maps decision trees~\cite{Khataei2025}.
These designs are one to two orders of magnitude faster than the
\SI{768}{\nano\second} reported here, but their weights are part of the circuit,
so every retraining requires a new bitstream.

\subsection{Positioning of This Work}
The design space thus has three points: LUT-mapped networks give nanoseconds
with per-model synthesis, overlays give re-programmability at per-frame
throughput, and the present engine gives sub-microsecond single-inference
latency with re-programmability on a low-cost part. The claim is the
conjunction of four properties, none individually novel: (i) single-inference
latency below one microsecond, given analytically and confirmed on hardware;
(ii) different topologies in one unchanged bitstream; (iii) an
Ethernet-to-decision path measured end to end and per stage; and (iv) bit-exact agreement
with an independent reference over $4\times10^{5}$ inferences.
Table~\ref{tab:related_work} positions the work; its latency figures are not
measured between the same points, and Section~\ref{sec:hls4ml} supplies a
like-for-like comparison with hls4ml.

\section{Architecture and Implementation}
\label{sec:framework}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsection{System Overview}
Fig.~\ref{fig:block_design} shows the partition. Ethernet frames are received
by the PS, which runs bare-metal lwIP and hands the feature vector to the PL
through AXI-DMA; the \texttt{mlp\_axi\_wrapper} receives the stream, runs the
core, and exposes the class scores over AXI-Lite. Each 32-bit stream word
carries two 16-bit $Q8.8$ values, and the 40 features, zero-padded to the
64-wide datapath, arrive as 32 words on which the engine starts. Feature
construction and quantization happen on the host, so the PS only copies the
received vector into a DMA buffer; the argmax over the three scores runs on the
PS after read-back and is counted in the readout stage of the latency
breakdown. A model is deployed by quantizing it on the host and writing the
weights, biases and layer widths over AXI-Lite; the bitstream is unchanged.

\begin{figure*}[t]
\centering
\includegraphics[width=\textwidth]{figures/system_architecture.pdf}
\caption{System architecture of the proposed framework on the Zynq-7000 SoC.
Market data arrives over Ethernet at the PS, which forwards the prepared
feature vector to the custom \texttt{mlp\_axi\_wrapper} core through
AXI-DMA / AXI-Stream; the model parameters are loaded and the final decision
is read back over AXI-Lite. The entire inference is executed by the 13-stage

\label{fig:block_design}

\subsection{Inference Core}
The core (\texttt{mlp\_engine}, Fig.~\ref{fig:microarch}) uses 192 DSP slices as
parallel multipliers; accumulation is done by a fabric adder tree rather than
inside the DSP blocks, which is why logic utilization is dominated by the
reduction network. The 13-stage pipeline has one address-issue stage (S0)
followed by twelve datapath stages: S1--2 read and register weights and inputs,
S3--4 multiply, S5--10 reduce through a balanced $64\!\rightarrow\!1$ tree, S11
adds the bias, and S12 rescales, saturates and applies ReLU. Each token carries
three neurons of 64 inputs, and two ping-pong buffers hold the inter-layer
activations so that every layer reuses the same multiplier array. Arithmetic is
$Q8.8$ with 40-bit accumulation, an arithmetic right shift and 16-bit
saturation; weights and biases reside in 195 block memories written through
AXI-Lite (address bit~17 selects configuration or memory).

\begin{figure*}[t]
\centering
\includegraphics[width=0.92\textwidth]{figures/mlp_engine_pipeline.png}
\caption{Pipeline datapath of the hardware MLP core (\texttt{mlp\_engine}).
After the address-issue stage (S0), stages 1 and 2 fetch the weights, inputs, and
bias from BRAM; stages 3 and 4 perform the 192 parallel $Q8.8$ multiplications on
the DSP slices; stages 5 to 10 form the balanced $64\!\rightarrow\!1$ adder tree;
stage 11 adds the bias; and stage 12 rescales and applies the ReLU before the
result is written back to the ping-pong activation buffers. The
\texttt{mlp\_axi\_wrapper} splits each 32-bit AXI-Stream word into two 16-bit
$Q8.8$ values and triggers the engine; weights/biases reside in BRAM and are
loaded via AXI-Lite (address bit~17 selects configuration vs.\ memory).}
\label{fig:microarch}
\end{figure*}

\subsection{Measurement Infrastructure}
The core exports a data-in pulse, one done pulse per layer and a busy signal on
debug pins, so per-layer timing can be observed with an oscilloscope. A 16-bit
cycle counter, cleared when \texttt{start} is accepted and latched when the
final layer finishes, is read back over AXI-Lite after every inference. The
firmware also timestamps each stage of the on-board path with the Zynq Global
Timer and returns the timestamps in the reply.

\subsection{Functional Verification of the Inference Core}
\label{sec:verification}
\subsubsection{Golden Reference Model}
A bit-accurate software model was written independently of the RTL. It
reproduces the host $Q8.8$ conversion with saturation, the truncating weight
conversion of the loader, the 40-bit accumulation, the shift, the 16-bit
saturation, ReLU on all but the output layer, and the argmax rule. A second,
cycle-accurate model of \texttt{mlp\_engine} reproduces the issue FSM, the token
pipeline, the one-cycle memory latency and the ping-pong write-back.

\subsubsection{Directed RTL Simulation}
Three directed tests isolate the multiply-reduce-rescale path, the bias pipeline
and the write-back indexing. Each writes its parameters through the same
AXI-Lite map as the loader, streams a stimulus over AXI-Stream, and compares
the outputs against hand-computed values; unused input positions are preloaded
with distinctive values so that a missing write cannot pass as correct. The
tests exposed three pipeline-alignment defects (Table~\ref{tab:rtl_defects}),
each a one-line index correction that changes neither depth, resources nor
timing. After correction the cycle-accurate model matched the golden reference
on 240 random cases (60 parameter sets $\times$ 4 inputs); the original
alignment matched none.

\subsubsection{On-Hardware Bit-Exact Verification}
The corrected design was verified on the board against the golden model with a
stimulus built to exercise saturation, ReLU, sign transitions and zero padding.
Recorded market data cannot do this: its features are clipped to $[-5,5]$ and
never drive the accumulator toward saturation. The firmware returns the three
raw 16-bit outputs with every decision, so the comparison is made on the
arithmetic and not only on the argmax. Across four networks the hardware
reproduced the golden model on all 400{,}000 inferences and 1{,}200{,}000 raw
outputs (Table~\ref{tab:verification}).

A reconfigurable engine needs one further check: if loader and model both
padded every network to the largest shape, they would agree while the shape
mechanism went untested. The golden model therefore evaluates each network at
its true topology, the loader writes the per-layer width registers before each
run, and the cycle counter records how many iterations the controller issued.
The four counts in Table~\ref{tab:verification} are distinct and each one cycle
below the prediction of \eqref{eq:cycles}, the offset being the counting
convention of Section~\ref{sec:determinism}; a padded network would have
produced four equal counts. The runs used the bitstream characterized in
Section~\ref{sec:resources}, compared byte for byte against the boot image.

\subsection{Dataset and Classification Task}
\label{sec:dataset}
The workload is a three-way directional classification on the public Binance
BTCUSDT aggregated-trade archive: \num{16631211} trades between 2025-05-01 and
2025-05-18. The 40 features come from a trailing window of 40 trades and are
dimensionless: 20 slots of relative price changes scaled by \num{1000} (one of
which is a constant zero left by zero-padding of the difference series), 10
quantities divided by the window mean, and 10 taker-side indicators of $\pm 1$.
Every feature is clipped to $[-5,5]$, so the integer part of $Q8.8$ has more
than four bits of headroom. With $r_t = (P_{t+50}-P_t)/P_t$, the label is
\emph{buy} for $r_t > \theta$, \emph{sell} for $r_t < -\theta$ and \emph{hold}
otherwise, with $\theta = 5\times10^{-5}$; larger thresholds leave the minority
classes at \SI{5}{\percent} or below \SI{0.1}{\percent}. The split is
chronological: the final \SI{10}{\percent}, \num{1663113} samples, is held out
(no embargo was applied; 50 boundary labels overlap the validation period). The
validation period contains \SI{57.16}{\percent} hold, \SI{21.50}{\percent} buy
and \SI{21.35}{\percent} sell, so the majority-class baseline is
\SI{57.16}{\percent}.

\subsection{Core Latency and Cycle Model}
The per-layer done pulses give the inter-pulse times of
Fig.~\ref{fig:scope_layer} and the total interval of Fig.~\ref{fig:scope_total}:
280, 200, 160 and \SI{118}{\nano\second} for layers 1 to 4, and
\SI{768}{\nano\second} in total. These values follow from the architecture. The
issue FSM emits one token of three neurons per cycle, so a layer of $n_\ell$
outputs needs $\lceil n_\ell/3\rceil$ issue cycles, and then waits for the
pipeline to empty:
\begin{equation}
c_\ell \;=\; \left\lceil \frac{n_\ell}{3} \right\rceil + D + 1,
\qquad D = 13.
\label{eq:cycles}
\end{equation}
Analytic models of this kind steer design-space exploration for systolic
accelerators to within about one percent~\cite{Gutermann2026}; for a
single-issue pipeline without data-dependent control the model can be exact.
The predicted total, 96 cycles or \SI{768}{\nano\second}, equals the measured
interval (Table~\ref{tab:cycle_breakdown}). Two per-layer readings are below the
prediction by less than one clock period, consistent with the reading
uncertainty of separate captures; the total is corroborated independently by
the cycle counter (Section~\ref{sec:determinism}).

Of the 96 cycles, 56 drain the pipeline between layers, so only
\SI{42}{\percent} of the core latency issues work; overlapping drain and issue
would need sub-layer double buffering and is left as future work. With 192
multipliers at \SI{125}{\mega\hertz} the peak is \SI{48}{GOP/s}; the reference
network performs 5168 useful multiply-accumulates while the zero-padded array
issues 7680, so the achieved rate is $2\times5168/\SI{768}{\nano\second}\approx
\SI{13.5}{GOP/s}$, \SI{28}{\percent} of peak. The core sustains \SI{1.30}{M}
inferences per second, and the system about \SI{0.77}{M} because the wrapper
does not overlap reception with computation; both far exceed what the host
path supplies.

\subsection{Determinism of the Hardware Core}
\label{sec:determinism}
Over \num{100000} consecutive inferences at line rate the cycle counter returned
95 every time: minimum, maximum and mean are equal and the standard deviation is
zero, irrespective of the input values, the activation pattern and concurrent
AXI-Lite and DMA traffic. The counter reads 95 where \eqref{eq:cycles} predicts
96 because it counts only non-idle cycles and so excludes the cycle in which
\texttt{start} is sampled; the start-to-done convention is used throughout.

\section{Baselines on the Same Device}
\label{sec:baselines}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsection{Sequential Hardware Baseline}
\label{sec:baseline}
An earlier version of this design, preserved in the artifact history, used a
sequential FSM driving a single multiply-accumulate unit with the network
dimensions hardwired. Each neuron costs one cycle for the bias, one per input
and three to activate, write and advance, so a layer occupies
$n_{\text{out}}(n_{\text{in}}+4)$ cycles; with layer transitions and a hardware
argmax the design required \num{5639} cycles, \SI{56.4}{\micro\second} at its
\SI{100}{\mega\hertz} clock. At a common \SI{125}{\mega\hertz} it would need
\SI{45.1}{\micro\second}, so the architecture alone accounts for a factor of
$58.7$; as deployed the factor is $73.4$, the remainder being the clock. The
factor compares controller cycle counts, \num{5639} against 96, and comes from
replacing the single unit with 192 parallel multipliers. The earlier design
also received its inputs through one AXI-Lite write per operand, which the
DMA-fed stream replaces; that change is outside both cycle counts and does not
contribute to the factor.

\subsection{Software Inference on the Cortex-A9}
\label{sec:arm_baseline}
The same network was implemented in C and run bare-metal on the
\SI{667}{\mega\hertz} Cortex-A9 with identical $Q8.8$ arithmetic, timed with the
Global Timer over \num{1000} inferences with warm caches and no network or DMA
activity. It requires \SI{52.4}{\micro\second} on average, 68 times the fabric.
The figure is for scalar \texttt{-O3} code on one core; without optimization the
same source needs \SI{302}{\micro\second}. It corresponds to about \num{34900}
cycles for 6704 multiply-accumulates (the first layer is padded to 64 inputs),
5.2 cycles each; a NEON implementation would narrow the gap and its absence is
a limitation.

The distributions differ more than the means. Software ranges from
\SI{51.2}{} to \SI{67.1}{\micro\second} (median \SI{52.0}{}, p99
\SI{52.6}{\micro\second}), a spread more than twenty times the whole hardware
inference, under conditions more favorable than any deployment; trained weights
change the mean by about two percent because ReLU is a data-dependent branch.
The hardware has no spread at all. The sequential hardware baseline, at
\SI{56.4}{\micro\second}, is slightly slower than optimized software, so the
gain comes from the parallel issue structure rather than from the change of
substrate. The software path also occupies the processor for its whole duration,
whereas the hardware path frees it as soon as the DMA descriptor is posted.

\subsection{Run-Time Reconfigurability and Scalability}
\label{sec:reconfig}
The per-layer output widths are AXI-Lite registers that the issue FSM reads to
derive its iteration counts, so the network shape is a run-time parameter. The
four networks of Table~\ref{tab:verification}, with first hidden layers from 10
to 64 neurons, were loaded into the same programmed device and each verified
bit-exactly, without re-synthesis or bitstream reload. Loading a network takes
$\sum_\ell\lceil n_\ell/3\rceil \times 3 \times 64$ weight writes plus biases,
about \num{7800} AXI-Lite transactions for the reference topology.

Because all 64 inputs of a neuron slot are multiplied in parallel, only the
number of output neurons enters the cycle count, so the four networks complete
in 69, 76, 95 and 111 counted cycles, \SIrange{560}{896}{\nano\second} start to
done, each constant over its run. The drain term of $4\times14$ cycles does not
depend on the shape, so it exceeds half the latency of the smaller networks.
The datapath is elaborated for at most four layers of at most 64 neurons and 64
inputs; any network within those bounds is hosted without re-synthesis. Beyond
them the limit is memory organization rather than arithmetic: one memory per
(neuron slot, input) pair means that wider inputs or more parallel neurons
multiply the block count, and packing several inputs per memory word is the
natural extension.

\subsection{Method}
The four networks of Table~\ref{tab:verification} were generated with
hls4ml~1.3.0~\cite{Schulte2026} for the XC7Z020-1CLG484 at an
\SI{8}{\nano\second} target, with Vitis HLS and Vivado 2025.2, and configured to
reproduce the engine's arithmetic: \texttt{ap\_fixed<16,8>} weights, biases and
activations, \texttt{ap\_fixed<40,24>} accumulation, truncation and saturation
on the result, and weights pre-quantized by the loader's conversion. On
\num{20000} stimulus inputs the C emulation of each model agreed with the golden
model on every raw output. Each network was generated with the
\texttt{Resource} strategy at reuse factors RF $\in\{8,16,32,64,128\}$, and every
design that fits the device was placed and routed out of context with an
\SI{8}{\nano\second} clock constraint. The HLS timing estimate was not used: on
the small networks points estimated at \SI{5.75}{\nano\second} routed at about
\SI{7.8}{\nano\second}, and on the large ones at up to \SI{11}{\nano\second}.

\subsection{Results}
Table~\ref{tab:hls4ml} and Fig.~\ref{fig:hls4ml} report the result. Only four
designs close timing at \SI{125}{\mega\hertz}: three of hls4ml and the engine.
On the two smaller networks hls4ml at RF~8 reaches 456 to \SI{457}{\nano\second}
against 560 and \SI{616}{\nano\second}, 1.2 to 1.35 times faster, at a cost of 84
and 201 DSP slices for a single network. On the two larger networks no hls4ml
point meets \SI{125}{\mega\hertz}: the designs with enough parallelism exceed
the LUT capacity or route at 91 to \SI{125}{\mega\hertz}, and even at its own
$f_{\max}$ the fastest hls4ml design takes \SI{1026}{\nano\second} against
\SI{768}{\nano\second} for 40-64-32-16-3 and \SI{1758}{\nano\second} against
\SI{896}{\nano\second} for 40-64-64-32-3.

Three qualifications apply, two in hls4ml's favor. The hls4ml designs were routed
out of context, without the PS, DMA and interconnect that share the device with
the engine. hls4ml pipelines successive inferences every II cycles by giving each
layer its own multipliers, so its throughput is far higher; the engine cannot
overlap inferences because the same 192 multipliers evaluate every layer in
turn. For single-inference latency this does not help, and even the engine's
\SI{1.30}{M} inferences per second is two orders of magnitude above the
\num{11000} to \num{12400} requests per second that the Linux host sustained with
one request in flight. Finally, each hls4ml row is a separate bitstream with its
weights compiled in, so changing or retraining a network costs a new synthesis
and place-and-route run, from a few minutes to over half an hour per point here,
whereas the engine runs all four networks from one bitstream at a fixed 192 DSP
slices.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Discussion}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
The results support four observations. First, embedding the network in the PL
makes the core latency a property of the pipeline: \SI{768}{\nano\second} with
no spread, while the host path around it varies from \SI{67}{} to
\SI{460}{\micro\second} in median across operating systems. Second, $Q8.8$ is
essentially accuracy-neutral here (at most 0.22 points across five models).
Third, the design fits a low-cost Zynq-7000 at an estimated \SI{2.70}{\watt}
with positive slack. Fourth, run-time shape does not cost latency against a
compiler that specializes the hardware: hls4ml is faster only on the two smaller
networks at its most parallel points, while on the two larger networks the
engine is 1.3 to 2.0 times faster than the fastest hls4ml design that fits.
Specialization buys throughput, through inference-level pipelining that the
engine does not implement.

The limitations are equally concrete. Only \SI{14.4}{\micro\second} of the
\SI{68.6}{\micro\second} end-to-end latency is on the board, and the features are
computed on the host, so the system as measured is not a complete trading path.
The power figure is an estimate, the software baseline is scalar, and the
evaluation uses one device and one task.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Conclusion}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
We presented an Ethernet-fed MLP inference engine in the programmable logic of a
low-cost Zynq-7000. A 192-multiplier, 13-stage pipelined core performs a $Q8.8$
inference in \SI{768}{\nano\second} with zero timing variance, using
\SI{27.0}{\percent} of the LUTs and \SI{87.3}{\percent} of the DSP slices of an
XC7Z020 at an estimated \SI{2.70}{\watt}, \SI{0.97}{\watt} of it in the PL. The
same network on the SoC's Cortex-A9 needs \SI{52.4}{\micro\second}, a factor of
68 on identical arithmetic, and the architecture accounts for a factor of
$58.7$ over an earlier sequential design at a common clock. The network shape is
a run-time parameter: four topologies ran in one unchanged bitstream, each at
its own cycle count, and against hls4ml on the same device, clock and arithmetic
this costs no single-inference latency on the larger networks, where no hls4ml
design closes timing at \SI{125}{\mega\hertz}. Correctness was established
bit-exactly over 400{,}000 inferences after directed simulation had exposed three
pipeline-alignment defects.

Two directions follow. Integrating an Ethernet MAC in the PL would remove the
host network stack from the dominant part of the path. Packing several inputs per
memory word would relax the present bounds of four layers of 64 neurons and 64
inputs without additional DSP cost.
